Como funciona o Taberna

O Taberna é uma base para sites pessoais, portfólios e páginas de apresentação. Ele reúne uma aplicação que organiza o site, arquivos de conteúdo que você pode editar e recursos para personalizar a apresentação.

Para trabalhar com o projeto, vale entender como essas partes se conectam: onde ficam os textos, como uma página é carregada, como os idiomas são escolhidos e o que precisa ser gerado para publicar o site.

A lógica do projeto

O Taberna funciona inteiramente no navegador. A aplicação Vue monta a estrutura da interface e carrega os arquivos HTML que compõem o conteúdo. A navegação entre páginas é controlada pelo Vue Router.

O conteúdo fica separado dos componentes da aplicação. Você pode revisar um texto ou alterar os links de um menu editando seus fragmentos HTML. Mudanças na estrutura do layout e nos comportamentos interativos ficam nos arquivos Vue.

O resultado pode ser hospedado como arquivos estáticos. O projeto não exige um backend para exibir suas páginas e não inclui banco de dados ou painel administrativo: a edição acontece nos arquivos do seu repositório.

Organização dos arquivos

Esta é uma visão simplificada das pastas e dos arquivos usados no dia a dia:

public/
  config/
    languages.json
  content/
    pt-br/
      home.htm
      pages/
        howwork.htm
        themes.htm
        templates.htm
        components.htm
        utilities.htm
      complements/
        brand.htm
        header-nav.htm
        sidebar-nav.htm
        footer.htm
        copyright.htm
    en-us/
  images/
  icons/
  fonts/
src/
  App.vue
  AppTemplate.vue
  router.ts
  templates/
    default.vue
  components/
  styles/
  style-customs.css
  1. public/content/: reúne o conteúdo, separado em pastas por idioma.
  2. home.htm: contém o corpo da página inicial daquele idioma.
  3. pages/: organiza os fragmentos das páginas internas.
  4. complements/: reúne os trechos compartilhados, como marca, menus e rodapé.
  5. public/config/languages.json: define os idiomas disponíveis e suas informações.
  6. public/images/, public/icons/ e public/fonts/: guardam recursos usados pelo site.
  7. src/templates/: contém os layouts que organizam as regiões da interface.
  8. src/components/: contém os componentes da aplicação.
  9. src/styles/: reúne as definições de tema, fontes, utilities e estilos globais.
  10. src/style-customs.css: concentra estilos personalizados do conteúdo, como os usados nesta documentação.

As pastas pages/ e complements/ ajudam a organizar o conteúdo. Os arquivos são carregados pelos caminhos informados nos links e na aplicação; colocá-los nessas pastas não cria entradas de menu automaticamente.

Como uma página é montada

Ao abrir o site, a aplicação inicia a identificação do idioma e monta a estrutura compartilhada das páginas. Os componentes de conteúdo aguardam a definição do idioma para buscar seus arquivos.

Cada parte tem uma responsabilidade:

  1. 1
    App.vue reúne a estrutura da aplicação, a página da rota atual e as telas de carregamento e erro.
  2. 2
    O template define onde ficam o cabeçalho, a área principal, o rodapé e o menu lateral.
  3. 3
    AppTemplate.vue preenche as regiões do template com os complementos e componentes correspondentes.
  4. 4
    O roteador determina qual conteúdo deve aparecer na área principal.
  5. 5
    O componente tbc-flux busca o fragmento no idioma ativo e insere seu HTML na página.

Por exemplo, a marca exibida no cabeçalho, no rodapé e no menu lateral vem do mesmo arquivo complements/brand.htm. Alterar esse fragmento atualiza o conteúdo usado nessas três regiões na próxima carga.

Ao navegar por um link interno, a área principal recebe o conteúdo da nova rota, mantendo a estrutura compartilhada do site.

Como escrever o conteúdo

Os arquivos .htm devem conter fragmentos HTML: apenas os elementos que serão exibidos naquela parte do site. Não é necessário repetir a estrutura de um documento completo HTML 5.

Use títulos para organizar os assuntos, parágrafos para desenvolver as ideias e listas quando houver uma sequência ou um conjunto de itens. Links e imagens também podem fazer parte dos fragmentos.

O conteúdo publicado é interpretado como HTML. O Taberna não converte Markdown automaticamente; se você usar Markdown para preparar um rascunho, precisa convertê-lo em HTML antes da versão final.

Os fragmentos podem usar classes de estilo e componentes personalizados registrados pelo projeto. Expressões e diretivas Vue, como interpolações e v-if, não são compiladas nesses arquivos. Comportamentos que dependem de Vue devem ser implementados nos componentes da aplicação.

Esses arquivos são conteúdo de autoria do responsável pelo site. O carregador não sanitiza o HTML, portanto publique apenas conteúdo que você conhece e revisou.

Páginas e navegação

Os links internos usam o formato com #. A página inicial está em #/, e o seletor de idiomas está em #/language.

Para as páginas de conteúdo, o trecho depois de #/ indica o caminho do fragmento dentro da pasta do idioma ativo. Por exemplo: 

Endereço: #/pages/howwork.htm
Idioma ativo: pt-br
Arquivo: public/content/pt-br/pages/howwork.htm

O mesmo endereço, com inglês ativo, procura public/content/en-us/pages/howwork.htm. O idioma não precisa aparecer no link.

Adicionando uma página

Para criar uma página chamada Sobre, siga esta sequência:

  1. 1
    Crie pages/about.htm dentro da pasta de cada idioma habilitado.
  2. 2
    Escreva o conteúdo correspondente em cada idioma, mantendo o mesmo nome e caminho do arquivo.
  3. 3
    Adicione o link nos complementos de navegação em que deseja disponibilizar a página.
  4. 4
    Confira o acesso à página e a troca de idioma no ambiente local.

O link pode ser escrito assim:

 <a href="#/pages/about.htm">Sobre</a>

O menu do cabeçalho e o menu lateral possuem arquivos separados: complements/header-nav.htm e complements/sidebar-nav.htm. Edite ambos quando quiser que a página apareça nas duas navegações.

Para esse tipo de página, a rota genérica já encaminha o caminho ao carregador; não é necessário cadastrar uma rota Vue para cada fragmento.

Caminhos e falhas de carregamento

Os caminhos dos fragmentos precisam terminar em .htm. No valor encaminhado ao carregador, não use uma barra inicial, barras invertidas, segmentos vazios ou ... Subpastas são permitidas, como em pages/about.htm.

Se um arquivo não existir, não puder ser carregado ou a hospedagem devolver um documento HTML completo no lugar do fragmento, a aplicação apresenta sua tela de erro. Atualmente, não há uma página de conteúdo não encontrado específica nem busca automática da tradução em outro idioma.

Como funcionam os idiomas

O arquivo public/config/languages.json reúne quatro informações:

  1. default: o idioma padrão.
  2. available: a lista de idiomas habilitados.
  3. flags: as bandeiras associadas a cada idioma.
  4. names: os nomes apresentados no seletor.

A configuração atual é:

{
  "default": "en-us",
  "available": ["pt-br", "en-us"],
  "flags": { "pt-br": "🇧🇷", "en-us": "🇺🇸" },
  "names": {
    "pt-br": "Português (Brasil)",
    "en-us": "English (United States)"
  }
}

Ao iniciar, o Taberna procura um idioma disponível nesta ordem:

  1. 1
    A preferência salva no navegador em uma visita anterior.
  2. 2
    As preferências de idioma informadas pelo navegador.
  3. 3
    O idioma padrão da configuração.
  4. 4
    O primeiro idioma disponível, caso o padrão não esteja na lista.

Use identificadores em letras minúsculas, como pt-br e en-us, e mantenha esses nomes nas pastas de conteúdo. A correspondência considera o identificador completo: uma preferência pt não é convertida automaticamente em pt-br.

Ao escolher outro idioma, a preferência é salva no armazenamento local do navegador e a página é recarregada, mantendo o endereço da página atual. Se o navegador impedir a gravação dessa preferência, a escolha pode não persistir.

Para habilitar outro idioma, adicione suas informações à configuração e prepare todos os fragmentos correspondentes, incluindo páginas e complementos. As traduções são escritas por você; não há tradução automática. Essa organização por idioma se aplica ao conteúdo, enquanto algumas mensagens da interface ainda estão fixas em inglês.

Personalização: o papel de cada recurso

Temas

O tema define a identidade visual compartilhada: cores, fontes, espaçamentos, bordas e outros detalhes. Suas variáveis ficam em src/styles/theme.css e são utilizadas pelos estilos e pelas utilities do projeto.

Alterar essas definições permite ajustar a aparência de várias regiões de forma consistente. Para conhecer a configuração visual, consulte a página de Temas.

Templates

Os templates definem a estrutura do layout. Eles organizam regiões como cabeçalho, conteúdo principal, rodapé e menu lateral e oferecem espaços, chamados slots, para receber o conteúdo.

Atualmente, existe o template src/templates/default.vue. O arquivo src/AppTemplate.vue importa esse template e conecta seus slots aos complementos e componentes da aplicação.

Com o tempo, serão criados diversos tipos de templates para diferentes propostas de site. Sinta-se à vontade para criar os seus, adaptando a estrutura às necessidades do seu projeto.

Criar um template envolve trabalhar no layout Vue e integrá-lo ao AppTemplate.vue; a aplicação não oferece um seletor automático de templates. A página de templates é o espaço para aprofundar essa personalização.

Componentes

Os componentes reúnem recursos e comportamentos reutilizáveis. Entre os elementos disponíveis para o conteúdo estão tbc-flux, que carrega fragmentos, tbc-language, que leva ao seletor de idiomas, e tbc-carousel, que organiza itens em um carrossel.

Cada componente possui sua própria finalidade e pode oferecer atributos de configuração. A página de componentes reúne o assunto em separado.

Utilities

As utilities são classes que aplicam regras visuais diretamente aos elementos HTML. O Taberna utiliza Tailwind CSS e classes próprias com o prefixo tbu-*, definidas em src/styles/utilities.css.

Elas ajudam a aplicar as cores do tema, espaçamentos, bordas e outros recursos sem repetir as mesmas regras de CSS em cada trecho de conteúdo. Os detalhes ficam na página de utilities.

Do desenvolvimento à publicação

Prepare sua cópia

Tenha Git, Node.js 24 e npm instalados. Você pode criar um fork do Taberna na sua conta do GitHub para manter suas personalizações em um repositório próprio.

Para começar a partir do repositório original:

git clone https://github.com/mineot/taberna.git
cd taberna
npm install

Se criou um fork, substitua o endereço do comando pelo endereço do seu repositório.

Trabalhe localmente

Inicie o servidor de desenvolvimento:

npm run dev

Abra o endereço informado no terminal. Edite os fragmentos de conteúdo e confira o resultado no navegador. Se necessário, recarregue a página para buscar novamente os arquivos alterados.

Uma sequência prática é personalizar a marca e a home, preparar as páginas internas, ajustar os menus e conferir o conteúdo em cada idioma. Depois, trabalhe no tema e nas demais adaptações visuais.

Gere e confira a versão de produção

Quando quiser preparar o site para publicação, execute:

npm run build

Esse comando verifica o TypeScript e gera os arquivos de produção em dist/. Os arquivos públicos, incluindo os fragmentos de conteúdo, são copiados para essa saída.

Para conferir o resultado localmente:

npm run preview

O preview serve para revisar o build antes de publicá-lo. Confira os links, as imagens, as páginas e a troca de idioma; o sucesso do build não valida se todas as traduções e todos os destinos dos links existem.

Publique o site

Envie o conteúdo de dist/ para a hospedagem estática escolhida. O processo de envio depende do serviço utilizado; o projeto não inclui um fluxo automático de publicação.

Se publicar em um subdiretório, confira os caminhos dos recursos nos fragmentos. Por exemplo, /images/logo.png aponta para a raiz do domínio, enquanto images/logo.png é relativo ao endereço-base da página exibida. Os caminhos não são resolvidos a partir da pasta do fragmento e não são reescritos automaticamente pelo build.

Mantenha as alterações nos arquivos de origem, gere um novo build e publique a saída atualizada. Dessa forma, seu repositório continua sendo a referência para o conteúdo e as personalizações do site.
