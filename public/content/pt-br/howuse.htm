Como usar o Taberna

Personalize a identidade, organize os idiomas e publique páginas sem precisar alterar a estrutura principal da aplicação.

O Taberna separa a configuração do site, o conteúdo editorial e os componentes visuais. Na maior parte do tempo, você trabalhará apenas com arquivos JSON e HTML dentro da pasta public.

Este guia apresenta a organização atual do projeto e mostra como essas partes se conectam, desde a escolha do idioma até a montagem de uma página completa.

Configuração

Identidade e navegação

Os arquivos em public/config definem idiomas, título, logotipo, descrição, menu, página inicial e rodapé.

Conteúdo

Páginas por idioma

Os arquivos em public/content guardam a página inicial, o rodapé e todas as páginas acessadas pelas rotas do site.

Apresentação

Componentes reutilizáveis

Os elementos twc-* organizam colunas, painéis, links, carrosséis e outros blocos dentro dos arquivos HTML.

Executando e publicando o projeto

Instale as dependências uma vez e use os comandos abaixo na raiz do projeto. O servidor de desenvolvimento permite revisar as alterações no navegador; a compilação valida os tipos e produz a versão estática. 

npm install
npm run dev
npm run build

Depois de npm run build, publique o conteúdo da pasta dist em uma hospedagem de arquivos estáticos. A configuração usa caminhos relativos, portanto o resultado pode ser hospedado na raiz de um domínio ou em um subdiretório.

Organização por idioma

Cada idioma habilitado precisa de duas partes correspondentes: um arquivo JSON em public/config e uma pasta dentro de public/content. O código do idioma identifica os dois. 

public/
├── config/
│   ├── languages.json
│   ├── pt-br.json
│   └── en-us.json
└── content/
    ├── pt-br/
    │   ├── home.htm
    │   ├── footer.htm
    │   ├── about.htm
    │   └── articles/
    │       └── article1.htm
    └── en-us/
        ├── home.htm
        ├── footer.htm
        ├── about.htm
        └── articles/
            └── article1.htm

Os nomes das páginas e das pastas devem permanecer iguais entre os idiomas. Apenas os textos exibidos são traduzidos. Assim, uma rota como #/about.htm funciona independentemente do idioma selecionado.

Mesmo com apenas um idioma

A separação continua obrigatória. Um site somente em português ainda precisa de public/config/pt-br.json e da pasta public/content/pt-br. O idioma faz parte do caminho usado pela aplicação para localizar cada arquivo.

Definindo os idiomas disponíveis

O arquivo public/config/languages.json é o manifesto global de idiomas. Ele informa qual idioma será usado como padrão e quais opções podem ser selecionadas pelo visitante. 

{
  "default": "pt-br",
  "available": ["pt-br", "en-us"],
  "flags": {
    "pt-br": "🇧🇷",
    "en-us": "🇺🇸"
  },
  "names": {
    "pt-br": "Português (Brasil)",
    "en-us": "English (United States)"
  }
}

default e available

A aplicação procura primeiro uma escolha válida salva, depois um idioma compatível entre as preferências do navegador e, por fim, usa default. available contém todos os códigos de idioma habilitados.

flags e names

flags associa uma bandeira a cada código, enquanto names fornece o nome apresentado no seletor de idiomas.

Para manter somente o português, o manifesto pode ser reduzido:

{
  "default": "pt-br",
  "available": ["pt-br"],
  "flags": {
    "pt-br": "🇧🇷"
  },
  "names": {
    "pt-br": "Português (Brasil)"
  }
}

Todo código incluído em available também precisa existir em flags e names, além de possuir sua configuração e sua pasta de conteúdo.

Use códigos minúsculos, como pt-br. Quando existe somente uma variante compatível, uma preferência mais ampla do navegador também pode selecioná-la, como pt para pt-br.

Configurando cada versão do site

Cada arquivo public/config/{idioma}.json é independente. Nele ficam a identidade e a navegação que serão usadas quando aquele idioma estiver ativo. 

{
  "title": "Taberna",
  "image": "images/logo.png",
  "description": "Uma breve apresentação do site.",
  "ownership": "© 2026 Seu Nome",
  "footer": "footer.htm",
  "home": "home.htm",
  "navigator": [
    { "text": "Artigos", "href": "#/articles.htm" },
    { "text": "Como usar", "href": "#/howuse.htm" },
    { "text": "Sobre", "href": "#/about.htm" }
  ]
}

title

Nome exibido na identidade visual e usado como título do documento no navegador.

image

Caminho da imagem dentro de public, sem incluir a palavra public no valor.

description

Resumo do site que pode ser exibido pelo componente de identidade e usado como descrição nos metadados do documento.

ownership

Texto de autoria ou direitos autorais mostrado no rodapé.

home e footer

Campos opcionais com os nomes dos arquivos HTML carregados da pasta de conteúdo do idioma. Sem home, a página inicial exibe No Home Page; sem footer, permanecem apenas a autoria e o crédito fixo do projeto.

navigator

Lista de links da navegação. Cada item possui o texto visível em text e o destino em href.

A configuração somente substitui a versão atual depois que o JSON e os arquivos indicados por home e footer terminam de carregar com sucesso. Um JSON inválido, um arquivo ausente ou uma resposta incompatível interrompe essa troca sem publicar uma configuração parcial.

Criando páginas e conteúdos

Os valores de home e footer são carregados diretamente da pasta do idioma ativo. Com a configuração anterior, a versão em português utiliza: 

public/content/pt-br/home.htm
public/content/pt-br/footer.htm

As outras páginas não precisam ser declaradas separadamente. O caminho presente na rota é procurado dentro da mesma pasta. Por exemplo:

Página simples

#/about.htm

Carrega public/content/pt-br/about.htm.

Página em subpasta

#/articles/article1.htm

Carrega public/content/pt-br/articles/article1.htm.

Os links internos usam a navegação por hash, começam com #/ e incluem a extensão .htm. Um link pode ser colocado na configuração ou diretamente no conteúdo: 

<twc-link
  href="#/about.htm"
  label="Conheça o projeto"
></twc-link>

Cada arquivo deve ser um fragmento HTML, sem <!doctype html> ou <html>, e precisa ser servido como text/html ou application/xhtml+xml. O nome da página deve terminar em .htm. Os segmentos de diretório aceitam letras, números, sublinhado e hífen.

Conteúdo equivalente em todos os idiomas

Se about.htm existe em português, crie também o arquivo correspondente nos outros idiomas habilitados. Manter os mesmos caminhos permite trocar o idioma sem precisar inventar rotas diferentes para cada tradução.

Como funcionam os web components

O arquivo src/web-components.ts importa componentes Vue e os registra no navegador com nomes iniciados por twc-. Depois desse registro, eles podem ser escritos como tags HTML dentro dos arquivos de conteúdo.

Cada elemento é registrado apenas uma vez. A opção shadowRoot: false mantém o componente no mesmo contexto visual da página, permitindo que ele utilize o tema e os estilos globais do Taberna. 

const elements = {
  "twc-brand": defineCustomElement(Brand, { shadowRoot: false }),
  "twc-link": defineCustomElement(Link, { shadowRoot: false }),
  "twc-panel": defineCustomElement(Panel, { shadowRoot: false })
};

Além dos componentes, é possível usar elementos HTML comuns, como títulos, parágrafos, listas, imagens, citações e blocos de código. O conteúdo é sanitizado antes de ser exibido, removendo elementos ou atributos potencialmente perigosos.

Scripts, eventos HTML e atributos perigosos são removidos. Links aceitam apenas os protocolos HTTP e HTTPS; um destino inválido perde o atributo href. Em twc-link, use external somente com um endereço HTTP ou HTTPS absoluto.

Segurança e falhas de carregamento

O navegador recebe uma Política de Segurança de Conteúdo que restringe scripts, estilos, fontes e imagens às origens permitidas. A sanitização com DOMPurify é uma segunda camada aplicada a todo fragmento HTML antes da renderização.

A aplicação diferencia falhas de rede, HTTP, arquivo ausente, tipo de conteúdo incorreto, JSON inválido e documento HTML completo. Na inicialização, uma falha oferece nova tentativa; nas páginas, arquivos ausentes e demais erros recebem estados separados.

As mensagens técnicas de carregamento, erro e página não encontrada ainda aparecem em inglês. O conteúdo editorial e a navegação já possuem versões por idioma.

Personalizando o tema visual

O arquivo src/style.css carrega o Tailwind CSS, src/styles/theme.css e, por último, src/styles/utilities.css. Essa ordem permite que o tema use os tokens do Tailwind e que os utilitários consumam as variáveis definidas pelo tema. 

@import 'tailwindcss';
@import '@style/theme.css';
@import '@style/utilities.css';

Fontes e integração com o Tailwind

As declarações @font-face carregam Roboto, Roboto Serif, Roboto Mono e Italianno a partir da pasta public/fonts. O bloco @theme associa essas famílias aos tokens --font-sans, --font-serif, --font-mono e --font-fancy, usados pelas classes correspondentes do Tailwind.

Tokens globais

As propriedades em :root formam a API visual do projeto. Componentes e utilitários referenciam esses tokens; portanto, alterar um valor no tema atualiza todos os lugares que o consomem.

Base e identidade

--duration, --skeleton, --texture e --spacing-* definem movimento, carregamento, textura e escalas de espaçamento.

--background-*, --text-*, --border-* e --emphasis-* controlam a paleta e os estados de destaque compartilhados.

Layout responsivo

--container-sm, --container-md e --container-lg definem o recuo horizontal do conteúdo por largura de tela.

--block-sm e --block-lg definem o espaçamento vertical dos blocos.

Navegação e estrutura

Os grupos --backdrop-*, --language-*, --icon-button-* e --navigator-* configuram controles e seus estados normal, hover e ativo.

--header-*, --sidebar-* e --footer-* controlam fundo, borda, textura e textos das áreas estruturais.

Componentes

--brand-* controla imagem, título e descrição; --carousel-* controla botões, indicadores e temporizador.

--panel-* configura borda, fundo e espaçamento dos painéis. --quote-* configura fundo, borda, título, texto, espaçamento e distância entre os elementos das citações.

Os valores numéricos de espaçamento e layout são multiplicadores do token --spacing do Tailwind nos lugares em que aparecem dentro de calc(). Cores, opacidades, durações, bordas e outros valores CSS diretos devem manter uma unidade compatível com a propriedade que os utiliza.

Para criar outra identidade visual, altere os valores existentes em :root. Prefira redefinir os tokens gerais; personalize um grupo de componente somente quando ele precisar fugir do padrão compartilhado. 

:root {
  --background-color: var(--color-neutral-900);
  --background-emphasis-color: var(--color-neutral-800);
  --emphasis-color: var(--color-emerald-500);
  --container-lg: 24;
  --quote-border-size: 3px;
}

Utilitários CSS do projeto

O arquivo src/styles/utilities.css declara classes reutilizáveis com @utility. Elas podem ser aplicadas em estilos Vue com @apply ou usadas diretamente no atributo class de um elemento.

Movimento e espaçamento

app-duration aplica a duração global e a curva ease-in-out às transições.

app-focus-ring aplica o contorno de foco visível usado pelos controles de teclado.

app-gap-sm, app-gap-md e app-gap-lg aplicam os três níveis de espaçamento entre itens.

app-padding-sm, app-padding-md e app-padding-lg aplicam os mesmos níveis como espaçamento interno.

Superfície e código

app-texture aplica a imagem definida por --texture como fundo repetido.

app-code destaca pequenos trechos de código com espaçamento horizontal, fonte monoespaçada fina e o fundo de ênfase. Use-a preferencialmente em um elemento <code>.

Contêiner responsivo

app-container aplica app-duration e usa --container-sm como recuo horizontal. A partir de 48rem, usa --container-md; a partir de 64rem, usa --container-lg.

Bloco responsivo

app-block também aplica app-duration. O espaçamento vertical usa --block-sm por padrão e --block-lg a partir de 48rem. 

.example-section {
  @apply app-container app-block app-gap-md flex flex-col;
}
<p>
  Edite <code class="app-code">src/styles/theme.css</code>.
</p>

Componentes disponíveis

twc-brand

Exibe a imagem e o título definidos na configuração. O atributo description acrescenta a descrição do site. 

<twc-brand description></twc-brand>

twc-link

Cria um link com ícone. Use href para o destino, label para o texto e external quando o endereço deve ser aberto em uma nova aba. Links externos precisam usar um endereço HTTP ou HTTPS absoluto; destinos inválidos são exibidos sem navegação. 

<twc-link
  href="https://example.com"
  label="Visitar site"
  external
></twc-link>

twc-panel

Agrupa qualquer conteúdo. emphasis aplica o fundo de destaque e o espaçamento interno; rounded adiciona cantos arredondados; e bordered adiciona a borda definida pelo tema. 

<twc-panel emphasis rounded>
  <p>Conteúdo em destaque.</p>
</twc-panel>

twc-quote

Destaca uma citação ou um trecho de conteúdo. O atributo opcional title exibe um título acima do conteúdo; quando omitido, somente os elementos colocados entre as tags são exibidos. 

<twc-quote title="Nota do autor">
  <p>Uma boa estrutura torna o conteúdo mais fácil de explorar.</p>
</twc-quote>

twc-columns

Organiza os filhos em colunas. cols aceita valores de 1 a 12, gap controla o espaço entre os itens e align aceita start, center ou end. Em telas pequenas, o conteúdo sempre ocupa uma única coluna. 

<twc-columns cols="3" gap="4" align="center">
  <div>Primeira coluna</div>
  <div>Segunda coluna</div>
  <div>Terceira coluna</div>
</twc-columns>

twc-rows

Empilha os filhos verticalmente. gap controla o espaçamento e align controla o alinhamento textual dos filhos diretos com start, center ou end. 

<twc-rows gap="4" align="start">
  <h2>Título da seção</h2>
  <p>Primeiro parágrafo.</p>
  <p>Segundo parágrafo.</p>
</twc-rows>

twc-carousel e twc-carousel-item

O carrossel recebe itens por meio de twc-carousel-item. O atributo limit define quantos itens aparecem por página no desktop; no celular, apenas um é mostrado por vez.

delay define o intervalo de avanço automático em milissegundos. Use delay="0" para desativá-lo. show-timer="false" oculta o indicador de tempo. Os valores padrão são limit="1", delay="5000" e temporizador visível. Ponteiro ou foco dentro do carrossel pausam o avanço temporariamente. A reprodução automática respeita a preferência de movimento reduzido, e os controles permitem navegar e pausar ou retomar manualmente. 

<twc-carousel limit="3" delay="5000" show-timer="true">
  <twc-carousel-item>
    <p>Primeiro item</p>
  </twc-carousel-item>
  <twc-carousel-item>
    <p>Segundo item</p>
  </twc-carousel-item>
  <twc-carousel-item>
    <p>Terceiro item</p>
  </twc-carousel-item>
</twc-carousel>

Exemplo de uma página completa

Os componentes podem ser combinados com HTML comum. O exemplo abaixo cria uma apresentação, uma área com duas colunas e um link para outra página do site. 

<twc-rows gap="6">
  <h1 class="text-4xl" style="color: var(--emphasis-color)">
    Meu projeto
  </h1>

  <p>Uma breve apresentação do conteúdo desta página.</p>

  <twc-columns cols="2" gap="4">
    <twc-panel emphasis rounded>
      <twc-rows gap="2">
        <h2 class="text-xl">Primeiro destaque</h2>
        <p>Descrição do primeiro assunto.</p>
      </twc-rows>
    </twc-panel>

    <twc-panel emphasis rounded>
      <twc-rows gap="2">
        <h2 class="text-xl">Segundo destaque</h2>
        <p>Descrição do segundo assunto.</p>
      </twc-rows>
    </twc-panel>
  </twc-columns>

  <twc-link
    href="#/about.htm"
    label="Saiba mais"
  ></twc-link>
</twc-rows>

Salve esse conteúdo como um arquivo .htm dentro da pasta do idioma. Depois, adicione um link no navigator ou em outra página para torná-lo acessível.

Checklist para publicar conteúdo

1. Defina os idiomas em config/languages.json.

2. Crie um arquivo de configuração para cada idioma.

3. Crie uma pasta de conteúdo para cada idioma.

4. Mantenha os mesmos nomes e caminhos entre as traduções.

5. Use caminhos internos iniciados por #/.

6. Inclua a extensão .htm nos links das páginas.

7. Utilize os componentes twc-* para organizar o layout.

8. Salve fragmentos HTML, sem doctype nem a tag html.

9. Substitua imagens e links de exemplo por destinos reais.

10. Teste a navegação em todos os idiomas habilitados.

11. Execute npm run build antes da publicação.

Criando um novo web component

Para ampliar a biblioteca, crie o componente Vue, importe-o em src/web-components.ts e registre uma nova tag. Como o HTML de conteúdo passa por sanitização, a tag e seus atributos também precisam ser adicionados à lista permitida em src/utils/html.util.ts, no padrão CUSTOM_ELEMENT_PATTERN e, quando necessário, em CUSTOM_ATTRIBUTES.

Essa validação mantém os arquivos de conteúdo flexíveis sem permitir que elementos não reconhecidos sejam executados na página.
