How to Use Taberna

Customize the identity, organize languages, and publish pages without changing the application's main structure.

Taberna separates site configuration, editorial content, and visual components. Most of the time, you will work only with JSON and HTML files inside the public directory.

This guide introduces the project's current organization and shows how these parts connect, from choosing a language to building a complete page.

Configuration

Identity and navigation

The files in public/config define languages, title, logo, description, navigation, home page, and footer.

Content

Pages for each language

The files in public/content hold the home page, footer, and every page accessed through the site's routes.

Presentation

Reusable components

The twc-* elements organize columns, panels, links, carousels, and other blocks inside HTML files.

Language-based organization

Each enabled language needs two corresponding parts: a JSON file in public/config and a directory inside public/content. The language code identifies both. 

public/
├── config/
│   ├── languages.json
│   ├── pt-br.json
│   └── en-us.json
└── content/
    ├── pt-br/
    │   ├── home.htm
    │   ├── footer.htm
    │   ├── about.htm
    │   └── articles/
    │       └── article1.htm
    └── en-us/
        ├── home.htm
        ├── footer.htm
        ├── about.htm
        └── articles/
            └── article1.htm

Page and directory names should remain the same across languages. Only visible text is translated. This allows a route such as #/about.htm to work regardless of the selected language.

Even with only one language

This separation is still required. A website available only in English still needs public/config/en-us.json and the public/content/en-us directory. The language is part of the path the application uses to locate each file.

Defining the available languages

The public/config/languages.json file is the global language manifest. It specifies which language is used by default and which options visitors can select. 

{
  "default": "pt-br",
  "available": ["pt-br", "en-us"],
  "flags": {
    "pt-br": "🇧🇷",
    "en-us": "🇺🇸"
  },
  "names": {
    "pt-br": "Português (Brasil)",
    "en-us": "English (America)"
  }
}

default and available

default defines the language used when there is no valid saved choice. available contains every enabled language code.

flags and names

flags associates a flag with each code, while names provides the name displayed in the language selector.

To keep only English, the manifest can be reduced to:

{
  "default": "en-us",
  "available": ["en-us"],
  "flags": {
    "en-us": "🇺🇸"
  },
  "names": {
    "en-us": "English (America)"
  }
}

Every code included in available must also exist in flags and names, and it must have its own configuration file and content directory.

Configuring each version of the site

Each public/config/{language}.json file is independent. It contains the identity and navigation used while that language is active. 

{
  "title": "Taberna",
  "image": "images/logo.png",
  "description": "A short introduction to the website.",
  "ownership": "© 2026 Your Name",
  "footer": "footer.htm",
  "home": "home.htm",
  "navigator": [
    { "text": "Articles", "href": "#/articles.htm" },
    { "text": "How to Use", "href": "#/howuse.htm" },
    { "text": "About", "href": "#/about.htm" }
  ]
}

title

The name displayed in the visual identity and beside the logo.

image

The path to an image inside public, without including the word public in the value.

description

A summary of the website that can be displayed by the brand component.

ownership

The authorship or copyright text displayed in the footer.

home and footer

The names of the HTML files loaded from the language's content directory to build the home page and footer.

navigator

A list of navigation links. Each item has visible text in text and its destination in href.

Creating pages and content

The values of home and footer are loaded directly from the active language's directory. With the previous configuration, the English version uses: 

public/content/en-us/home.htm
public/content/en-us/footer.htm

Other pages do not need to be declared separately. The path in the route is looked up inside the same directory. For example:

Simple page

#/about.htm

Loads public/content/en-us/about.htm.

Page in a subdirectory

#/articles/article1.htm

Loads public/content/en-us/articles/article1.htm.

Internal links use hash navigation, begin with #/, and include the .htm extension. A link can be added to the configuration or directly to the content: 

<twc-link
  href="#/about.htm"
  label="Learn about the project"
></twc-link>

Equivalent content in every language

If about.htm exists in English, create the corresponding file in every other enabled language. Keeping the same paths allows visitors to switch languages without requiring different routes for each translation.

How web components work

The src/web-components.ts file imports Vue components and registers them in the browser with names beginning with twc-. Once registered, they can be written as HTML tags inside content files.

Each element is registered only once. The shadowRoot: false option keeps the component in the same visual context as the page, allowing it to use Taberna's theme and global styles. 

const elements = {
  "twc-brand": defineCustomElement(Brand, { shadowRoot: false }),
  "twc-link": defineCustomElement(Link, { shadowRoot: false }),
  "twc-panel": defineCustomElement(Panel, { shadowRoot: false })
};

In addition to the components, you can use standard HTML elements such as headings, paragraphs, lists, images, quotations, and code blocks. Content is sanitized before it is displayed, removing potentially dangerous elements or attributes.

Customizing the visual theme

The src/style.css file loads Tailwind CSS, src/styles/theme.css, and finally src/styles/utilities.css. This order allows the theme to use Tailwind tokens and the utilities to consume the variables defined by the theme. 

@import 'tailwindcss';
@import '@style/theme.css';
@import '@style/utilities.css';

Fonts and Tailwind integration

The @font-face declarations load Roboto, Roboto Serif, Roboto Mono, and Italianno from the public/fonts directory. The @theme block associates these families with the --font-sans, --font-serif, --font-mono, and --font-fancy tokens used by the corresponding Tailwind classes.

Global tokens

The properties in :root form the project's visual API. Components and utilities reference these tokens, so changing a value in the theme updates every place that consumes it.

Foundation and identity

--duration, --skeleton, --texture, and --spacing-* define motion, loading, texture, and spacing scales.

--background-*, --text-*, --border-*, and --emphasis-* control the shared palette and emphasis states.

Responsive layout

--container-sm, --container-md, and --container-lg define the content's horizontal padding for each screen width.

--block-sm and --block-lg define the blocks' vertical spacing.

Navigation and structure

The --backdrop-*, --language-*, --icon-button-*, and --navigator-* groups configure controls and their default, hover, and active states.

--header-*, --sidebar-*, and --footer-* control the background, border, texture, and text of the structural areas.

Components

--brand-* controls the image, title, and description; --carousel-* controls buttons, indicators, and the timer.

--panel-* configures panel borders, backgrounds, and spacing. --quote-* configures quotation backgrounds, borders, titles, text, padding, and gaps.

Numeric spacing and layout values are multipliers of Tailwind's --spacing token wherever they appear inside calc(). Colors, opacities, durations, borders, and other direct CSS values must retain a unit that is compatible with the property that consumes them.

To create a different visual identity, change the existing values in :root. Prefer redefining general tokens; customize a component group only when it needs to differ from the shared defaults. 

:root {
  --background-color: var(--color-neutral-900);
  --background-emphasis-color: var(--color-neutral-800);
  --emphasis-color: var(--color-emerald-500);
  --container-lg: 24;
  --quote-border-size: 3px;
}

Project CSS utilities

The src/styles/utilities.css file declares reusable classes with @utility. They can be applied in Vue styles with @apply or used directly in an element's class attribute.

Motion and spacing

app-duration applies the global duration and the ease-in-out timing function to transitions.

app-gap-sm, app-gap-md, and app-gap-lg apply the three levels of spacing between items.

app-padding-sm, app-padding-md, and app-padding-lg apply the same levels as inner spacing.

Surface and code

app-texture applies the image defined by --texture as a repeating background.

app-code highlights short code fragments with horizontal padding, a thin monospaced font, and the emphasized background. Prefer using it on a <code> element.

Responsive container

app-container applies app-duration and uses --container-sm as horizontal padding. From 48rem, it uses --container-md; from 64rem, it uses --container-lg.

Responsive block

app-block also applies app-duration. Its vertical padding uses --block-sm by default and --block-lg from 48rem. 

.example-section {
  @apply app-container app-block app-gap-md flex flex-col;
}
<p>
  Edit <code class="app-code">src/styles/theme.css</code>.
</p>

Available components

twc-brand

Displays the image and title defined in the configuration. The description attribute adds the website description. 

<twc-brand description></twc-brand>

twc-link

Creates a link with an icon. Use href for the destination, label for its text, and external when the address should open in a new tab. 

<twc-link
  href="https://example.com"
  label="Visit website"
  external
></twc-link>

twc-panel

Groups any kind of content. emphasis applies the emphasized background and inner spacing; rounded adds rounded corners. 

<twc-panel emphasis rounded>
  <p>Emphasized content.</p>
</twc-panel>

twc-quote

Highlights a quotation or a section of content. The optional title attribute displays a heading above the content; when omitted, only the elements placed between the tags are displayed. 

<twc-quote title="Author's note">
  <p>A good structure makes content easier to explore.</p>
</twc-quote>

twc-columns

Arranges its children in columns. cols accepts values from 1 to 12, gap controls the space between items, and align accepts start, center, or end. On small screens, content always uses a single column. 

<twc-columns cols="3" gap="4" align="center">
  <div>First column</div>
  <div>Second column</div>
  <div>Third column</div>
</twc-columns>

twc-rows

Stacks its children vertically. gap controls spacing and align positions each item at the start, center, or end of the available space. 

<twc-rows gap="4" align="start">
  <h2>Section title</h2>
  <p>First paragraph.</p>
  <p>Second paragraph.</p>
</twc-rows>

twc-carousel and twc-carousel-item

The carousel receives its items through twc-carousel-item. The limit attribute defines how many items appear on each page on desktop; on mobile, only one is displayed at a time.

delay defines the automatic advance interval in milliseconds. Use delay="0" to disable it. show-timer="false" hides the timer. When the pointer remains over the carousel, automatic movement is temporarily paused. 

<twc-carousel limit="3" delay="5000" show-timer="true">
  <twc-carousel-item>
    <p>First item</p>
  </twc-carousel-item>
  <twc-carousel-item>
    <p>Second item</p>
  </twc-carousel-item>
  <twc-carousel-item>
    <p>Third item</p>
  </twc-carousel-item>
</twc-carousel>

Example of a complete page

Components can be combined with standard HTML. The example below creates an introduction, an area with two columns, and a link to another page on the website. 

<twc-rows gap="6">
  <h1 class="text-4xl" style="color: var(--emphasis-color)">
    My project
  </h1>

  <p>A short introduction to the content on this page.</p>

  <twc-columns cols="2" gap="4">
    <twc-panel emphasis rounded>
      <twc-rows gap="2">
        <h2 class="text-xl">First highlight</h2>
        <p>A description of the first subject.</p>
      </twc-rows>
    </twc-panel>

    <twc-panel emphasis rounded>
      <twc-rows gap="2">
        <h2 class="text-xl">Second highlight</h2>
        <p>A description of the second subject.</p>
      </twc-rows>
    </twc-panel>
  </twc-columns>

  <twc-link
    href="#/about.htm"
    label="Learn more"
  ></twc-link>
</twc-rows>

Save this content as an .htm file inside the language directory. Then add a link to navigator or another page to make it accessible.

Content publishing checklist

1. Define the languages in config/languages.json.

2. Create a configuration file for each language.

3. Create a content directory for each language.

4. Keep the same names and paths across translations.

5. Use internal paths beginning with #/.

6. Include the .htm extension in page links.

7. Use the twc-* components to organize the layout.

8. Test navigation in every enabled language.

Creating a new web component

To expand the library, create the Vue component, import it into src/web-components.ts, and register a new tag. Because HTML content is sanitized, the tag and its attributes must also be added to the allowlist in src/components/layouts/content.vue.

This validation keeps content files flexible without allowing unrecognized elements to run on the page.
