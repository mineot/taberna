Components

Taberna's components offer reusable features for the site's content. With them, you can load a fragment, provide access to languages, or organize a sequence of elements into a carousel.

This page presents the available components, their attributes, and usage examples in the HTML files. The appearance can be complemented with the theme settings and the classes described in utilities.

How the components work

The components available to the fragments are registered as custom browser elements. Their names use the prefix tbc-*, and registration happens in src/web-components.ts during application initialization.

Element Purpose
tbc-flux Load an HTML fragment in the active language.
tbc-language Present the current language and lead to the language switcher.
tbc-carousel Organize elements into pages with navigation and optional autoplay.

Not every Vue component in the project is available as a custom tag. The loading and error screens, for example, are internal components mounted by the application. To make a new component available in fragments, you must register it.

The current elements were prepared to work inside Taberna, with their styles and their initialization. Components that query the language depend on the application's shared state; copying their tags into an isolated HTML page does not reproduce that environment.

How to write tags and attributes

In HTML fragments, use kebab-case attribute names and explicitly close custom tags: 

<tbc-language></tbc-language>

A property name such as totalPerPage in the Vue component corresponds to the total-per-page attribute in HTML. Numeric values are written as attributes, for example interval="5000".

To enable a boolean property, use the attribute with no value. To keep its default value of false, omit the attribute: 

<tbc-language flag-only></tbc-language>

Avoid writing flag-only="false" to disable the option: that value is text and does not represent the boolean false in this usage. Simply remove flag-only.

Fragments are inserted as HTML, without compiling Vue expressions or directives. Syntaxes such as :interval, v-if, v-for, and @click belong to the application's Vue files, not to content fragments.

tbc-flux: loading fragments

tbc-flux fetches a content file and inserts its HTML where the component is placed. The application uses this feature to assemble pages and complements, such as the brand, menus, and footer.

Attribute Type Default Purpose
content-file Text Not set Path of the fragment inside the active language's folder.

To reuse the site's brand:

<tbc-flux content-file="complements/brand.htm"></tbc-flux>

With Portuguese active, the component looks for content/pt-br/complements/brand.htm from the application's base address. In the project files, this corresponds to public/content/pt-br/complements/brand.htm.

The language name must not be part of the attribute. Thus, the same component uses the equivalent fragment when another language is chosen.

Path rules

The path must end in .htm, may contain subfolders, and must not begin with /. The loader also rejects backslashes, empty segments, and paths containing ...

The file must contain an HTML fragment, without the full structure of a document. The loader has a basic check for responses beginning with <!doctype html or <html, as can happen when the hosting provider returns the main page in place of a missing file.

Loading behavior

  1. Without content-file, with an empty attribute, or before the language is defined, the component remains empty and does not fetch.
  2. When the observed file or language changes, it clears the previous content and starts a new load.
  3. Fetch or validation failures are forwarded to the application's error screen.
  4. There is no automatic lookup of the same file in another language when a translation is missing.
  5. Each instance makes its own request; there is no cache or deduplication in the component's code.

There is also no cancellation or protection against stale responses on rapid attribute changes. This observation matters if you control the component dynamically through code.

Avoid circular inclusions: a fragment must not load itself, nor load another file that includes the first one again. This can create a continuous sequence of components and requests.

The HTML is inserted without sanitization. Use fragments reviewed and maintained by the person responsible for the site. In the Vue integration, the component also emits click, used by the sidebar to close after an interaction; binding that event lives in the Vue file.

tbc-language: language access

tbc-language presents the flag and name of the active language as a link to #/language.

Attribute Type Default Purpose
flag-only Boolean false Hide the name and show only the flag.

To show flag and name:

<tbc-language></tbc-language>

To show only the flag:

<tbc-language flag-only></tbc-language>

The component queries the names and flags defined in public/config/languages.json. This information is only available after the language is detected.

It provides access to the chooser page; it does not switch the language directly. Switching happens in the chooser, saves the preference in the browser, and reloads the page.

In the Vue integration, the component emits click. The default template uses this event to close the sidebar when the visitor accesses the chooser.

For clearer identification, prefer the version with the visible name when there is space. The flag-only version does not add a specific text label to the internal link.

tbc-carousel: content in pages

tbc-carousel organizes its child elements into pages. Each direct element inside the tag is considered an item; there is no additional carousel item tag.

Attribute Type Default Purpose
total-per-page Number 3 Number of items per page starting at 48rem.
interval Number 3000 Autoplay interval, in milliseconds. 0 disables autoplay.

Organizing the items

Each item can bring together a title, text, image, and links. For these elements to be part of the same item, place them inside a single element, such as article.

This example shows two items per page on larger screens and changes page every five seconds: 

<tbc-carousel total-per-page="2" interval="5000">
  <article>
    <h2>First project</h2>
    <p>A presentation of the first work.</p>
  </article>
  <article>
    <h2>Second project</h2>
    <p>A presentation of the second work.</p>
  </article>
  <article>
    <h2>Third project</h2>
    <p>A presentation of the third work.</p>
  </article>
</tbc-carousel>

Placing all articles inside a single div directly under the carousel would make that div count as a single item. Loose texts also do not replace the elements that represent the items.

Adapting to screen width

Below 48rem, the component shows one item per page. At and above that width, it uses total-per-page. The last page may contain fewer items than the previous ones.

On larger screens, pagination uses clickable indicators. On smaller ones, a counter for the current page and the total pages appears. The previous and next buttons let you move through the pages, returning to the start after the last and to the end before the first.

If there is at most one page, the navigation controls and the carousel footer are hidden.

Automatic and manual playback

To keep only manual navigation, use interval="0": 

<tbc-carousel total-per-page="1" interval="0">
  <article>
    <h2>First presentation</h2>
    <p>Content the visitor can read at their own pace.</p>
  </article>
  <article>
    <h2>Second presentation</h2>
    <p>Other content accessible through the navigation controls.</p>
  </article>
</tbc-carousel>

With a positive interval and more than one page, the carousel offers a pause/play button and a countdown to the next change. Navigating to another page restarts that interval.

In the initial automatic mode, playback pauses while the pointer is over the carousel or focus remains inside it. When these conditions end, the countdown may continue from the remaining time. A pause made with the button remains until the visitor triggers playback.

When the browser reports a preference for reduced motion, autoplay does not start. If the visitor explicitly triggers Play, playback becomes allowed and no longer pauses automatically on pointer or focus. The visual sliding transition remains disabled under reduced motion.

Values and item changes

total-per-page is rounded down and clamped to at least 1; non-finite values result in 1. The interval does not go below zero, and non-finite values disable autoplay. When authoring attributes, use valid numbers, with a whole and positive item count.

The component observes the addition and removal of direct elements to update the item count. Changes in screen width also recalculate the grouping. When leaving the page, its observers, listeners, and timers are removed.

Icons

Icons have a separate registry in src/web-icons.ts and use the prefix icon-*. The initially available element is icon-home, based on the Home icon from @lucide/vue.

You can combine it with a text that identifies the link's destination:

<a href="#/">
  <icon-home aria-hidden="true"></icon-home>
  <span>Home page</span>
</a>

In this example, the text communicates the action and the icon works as a visual complement. The current registry does not declare specific attributes to configure icon-home.

Adding icons as needed

You can add other icons as the project needs them. To make them available in fragments:

  1. 1
    Import the desired icon from @lucide/vue in src/web-icons.ts.
  2. 2
    Add an entry to the icons object, using the existing createIcon function.
  3. 3
    Choose a name with the icon-* prefix.
  4. 4
    Use the new tag in fragments after updating the application.

The existing entry serves as a reference for the registration pattern:

const icons = {
  ...createIcon('icon-home', Home),
};

Adding an icon to the registry lets you use it in content; writing a tag with a new name, without registering its component, does not load the icon automatically.

Appearance and accessibility

Custom elements use the page's DOM, without Shadow DOM. This allows sharing Taberna's global styles, but the reach of a rule still depends on its selectors and the use of scoped styles in the components.

You can apply utilities to the items' content, use the theme colors, and create global styles when necessary. Do not assume that a class applied to the outer tag controls all the component's internal elements.

The carousel uses --carousel-dot for the indicators, --carousel-dot-active for the active indicator, and --carousel-counter for the countdown. The playback interval is still configured through the interval attribute, not through a theme variable.

The carousel controls are buttons with accessible names and a visual focus indication. Items outside the current page receive inert and aria-hidden, becoming unavailable for interaction and hidden from the accessibility tree while they are not visible.

The carousel's interface labels are still fixed in English. Translating the items' content does not automatically translate those labels.

When preparing content, use headings in a proper hierarchy, clear link text, and alternative descriptions on images. These cares depend on the items' authorship, in addition to the features offered by the component.

Creating new components

If the site needs another reusable feature, create a Vue component in src/components/ and register it in src/web-components.ts.

Define the component and its properties

As a structural example, a notice.vue component could receive a message: 

<template>
  <p>{{ props.message }}</p>
</template>

<script setup lang="ts">
const props = defineProps({
  message: {
    type: String,
    default: '',
  },
});
</script>

This file would be compiled as part of the application. Vue expressions work in it because it is a component, unlike the HTML loaded in fragments.

Register the element

In src/web-components.ts, import the new file:

import Notice from '@/components/notice.vue';

Then add this entry to the elements object, preserving the existing registrations: 

...createElement('tbc-notice', Notice),

With the registration in place, the usage in content would be:

<tbc-notice message="See what's new in the project."></tbc-notice>

This component is only a creation example; tbc-notice is not part of the elements currently registered in Taberna.

Take care of the integration

Define attributes with clear names, default values, and appropriate validation. For components that receive content through slots, also consider how their styles will reach the elements provided by the author.

When a style block uses Tailwind directives, place @reference "@/style.css"; at the beginning. Reuse the theme variables and utilities to maintain visual consistency.

The current registrations do not install Pinia individually in each custom element. Components that use the stores depend on the Taberna application being initialized; if you want to distribute them as standalone widgets, that integration will need to be prepared separately.

Check the new element in a real fragment, with its attributes, content, and interactions. Verify keyboard use, presentation on different screens, and cleanup of timers or observers when present. Run npm run typecheck and npm run build and document the tag name and its attributes for whoever will use it.
