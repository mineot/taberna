Components

Taberna components provide reusable features for your site's content. You can use them to build layouts, organize navigation, open a sidebar, load fragments, offer language selection, and display content in a carousel.

This page covers the available components, their attributes, and examples for HTML files. You can customize their appearance with theme settings and the classes described in utilities.

How components work

Components available to fragments are registered as browser custom elements. Their names use the prefix tbc-*, and they are registered in src/web-components.ts during application startup.

Element Purpose
tbc-flux Load an HTML fragment in the active language.
tbc-language Display the current language and link to the language selector.
tbc-carousel Group elements into pages with navigation and optional autoplay.
tbc-link Follow a link or assign a property on another element.
tbc-nav Arrange links in rows, columns, or responsive groups.
tbc-sidebar Display a sidebar with a backdrop.
tbc-header Compose the header with branding and content.
tbc-footer Compose the footer with branding, navigation, body content, and copyright.
tbc-layout-linear Arrange the header, main content, and footer.

Not every Vue component in the project is available as a custom tag. Loading and error screens, for example, are internal components mounted by the application. To make a new component available in fragments, you need to register it.

The current elements are designed to work within Taberna, using its styles and initialization. Components that access the language depend on shared application state; copying their tags into a standalone HTML page does not recreate that environment.

Writing tags and attributes

In HTML fragments, use kebab-case attribute names and explicitly close custom tags:

<tbc-language></tbc-language>

A property name such as totalPerPage in a Vue component corresponds to the attribute total-per-page in HTML. Numeric values are written as attributes, for example interval="5000".

To enable a Boolean property, include the attribute without a value. To keep its default false value, omit the attribute: 

<tbc-language flag-only></tbc-language>

Avoid writing flag-only="false" to disable the option: this is a text value, not the Boolean false in this context. Simply remove flag-only.

Fragments are inserted as HTML, without compiling Vue expressions or directives. Syntax such as :interval, v-if, v-for and @click belongs in the application's Vue files, not in content fragments.

tbc-link: navigation and actions

Without trigger, the component creates a link. With trigger, it creates a button that assigns a value to a property on another element. In both cases, it applies tbu-link.

Attribute Default Usage
href /# Link destination. Use #/ for the home page relative to the application.
target _self The browsing context in which the link opens.
text null Control text; when omitted or empty, the slot content is used.
trigger null CSS selector for the element that receives the assignment.
trigger-prop null JavaScript property name, using camelCase for names with multiple words.
trigger-value null Value to assign. The strings true and false are converted to Booleans. 
<tbc-link href="#/pages/howwork.htm" text="How it works"></tbc-link>
<tbc-link href="#/">
  <icon-home aria-hidden="true"></icon-home>
  <span>Home</span>
</tbc-link>
<tbc-link trigger="#sidebar" trigger-prop="show" trigger-value="true"
  text="Open menu"></tbc-link>

The action's target must exist and already have the specified property. Invalid selectors, missing targets, and nonexistent properties are ignored. Only the first matching element is used. Other attribute values remain text; objects and arrays require property assignment or Vue bindings and are not parsed from JSON.

tbc-nav: navigation

The unnamed slot receives the items for a regular navigation group. The Boolean attribute vertical arranges them in a column. Use aria-label to identify the navigation: 

<tbc-nav vertical aria-label="Project guides">
  <tbc-link href="#/pages/themes.htm" text="Theme"></tbc-link>
  <tbc-link href="#/pages/components.htm" text="Components"></tbc-link>
</tbc-nav>

With responsive, provide the slots nav-wide and nav-narrow on actual elements. The first appears at widths of at least 48rem; the second appears below that width. In this mode, the unnamed slot is not displayed and no menu button is created automatically. 

<tbc-nav responsive aria-label="Main navigation">
  <div slot="nav-wide">
    <tbc-link href="#/" text="Home"></tbc-link>
    <tbc-link href="#/pages/components.htm" text="Components"></tbc-link>
  </div>
  <div slot="nav-narrow">
    <tbc-link trigger="#sidebar" trigger-prop="show" trigger-value="true"
      text="Open menu"></tbc-link>
  </div>
</tbc-nav>

vertical also works with responsive, changing the orientation of both groups. The elements assigned to the slots inherit the navigation's direction, wrapping, and spacing.

tbc-sidebar: side panel

The Boolean property show starts as false. The panel provides sidebar-header, the unnamed slot for the body, and sidebar-footer. 

<tbc-link trigger="#example-menu" trigger-prop="show" trigger-value="true"
  text="Open navigation"></tbc-link>
<tbc-sidebar id="example-menu">
  <div slot="sidebar-header">Navigation</div>
  <tbc-nav vertical>
    <tbc-link href="#/" text="Home"></tbc-link>
    <tbc-link href="#/pages/howwork.htm" text="How it works"></tbc-link>
  </tbc-nav>
  <div slot="sidebar-footer"><tbc-language></tbc-language></div>
</tbc-sidebar>

The internal icon and backdrop close the panel. For the custom element, closing also updates show, allowing it to be opened again with tbc-link. For an imported Vue component, use <Sidebar v-model:show="isOpen">; the event update:show communicates that the panel has closed.

Body links do not close the panel automatically. The menu does not yet implement Escape handling, focus trapping and restoration, or disabling off-screen elements. Consider these limitations when building your navigation.

tbc-header and tbc-footer: site regions

Component Slots
tbc-header header-brand for branding; the unnamed slot for content, usually navigation.
tbc-footer footer-brand, footer-nav, footer-copyright and the unnamed slot for the body. 
<tbc-header>
  <div slot="header-brand">My site</div>
  <tbc-nav><tbc-link href="#/" text="Home"></tbc-link></tbc-nav>
</tbc-header>
<tbc-footer>
  <div slot="footer-brand">My site</div>
  <div slot="footer-nav"><tbc-link href="#/pages/contribute.htm" text="Contribute"></tbc-link></div>
  <p>Additional information.</p>
  <div slot="footer-copyright">© 2026 My site</div>
</tbc-footer>

The header uses tbu-header and stays at the top while scrolling. The footer uses tbu-footer and includes the “Powered by Mineot” link. Compose these regions in the application shell to avoid repeating headers and footers inside each page.

tbc-layout-linear: page composition

Combines the header and footer in a column with a minimum height of one viewport. The slots are header-brand, header-nav, footer-brand, footer-nav, footer-body, footer-copyright and the unnamed slot for the main content.

The sidebar is composed separately. The properties owner, year and copyright are declared in the layout but do not generate text in the current footer; fill the slot footer-copyright. See the complete integration in the guide to .

tbc-flux: loading fragments

The tbc-flux fetches a content file and inserts its HTML where the component is placed. The application uses this to assemble pages and shared fragments, such as branding, menus, and the footer.

Attribute Type Default Purpose
content-file Text Undefined Fragment path within the active language's folder.

To reuse the site branding:

<tbc-flux content-file="complements/brand.htm"></tbc-flux>

With English active, the component looks for content/en-us/complements/brand.htm relative to the application's base URL. In the project files, this corresponds to public/content/en-us/complements/brand.htm.

The language name should not be part of the attribute. This lets the same component use the equivalent fragment when another language is selected.

Path rules

The path must end in .htm, may contain subfolders, and must not start with /. The loader also rejects backslashes, empty segments, and paths containing ...

The file must contain an HTML fragment, without a full document structure. The loader performs a basic check for responses starting with <!doctype html or <html, which can happen when the host returns the main page instead of a missing file.

Loading behavior

  • Without content-file, with an empty attribute, or before the language is resolved, the component stays empty and does not fetch content.
  • When the observed file or language changes, it clears the previous content and starts loading again.
  • Fetch or validation failures are forwarded to the application's error screen.
  • There is no automatic lookup of the same file in another language when a translation is missing.
  • Each instance makes its own request; the component code has no cache or request deduplication.

There is also no cancellation or protection against stale responses when attributes change quickly. This matters if you control the component dynamically through code.

Avoid circular includes: a fragment should not load itself or load another file that includes the first one again. This can create an endless chain of components and requests.

HTML is inserted without sanitization. Use fragments reviewed and maintained by the site owner. In Vue integration, the component also emits click, used by the sidebar to close after an interaction; this event is connected in the Vue file.

tbc-language: access to languages

The tbc-language displays the active language's flag and name as a link to #/language.

Attribute Type Default Purpose
flag-only Boolean false Hide the name and display only the flag.
lg Boolean false Larger text (text-xl).
sm Boolean false Smaller text (text-sm). Use only one size at a time.

To display the flag and name:

<tbc-language></tbc-language>

To display only the flag:

<tbc-language flag-only></tbc-language>

The component reads the names and flags defined in public/config/languages.json. This information is only available after language detection.

It links to the selection page; it does not change the language directly. The selector handles the change, saves the preference in the browser, and reloads the page.

In Vue integration, the component emits click. AppTemplate.vue uses this event to close the sidebar when the visitor opens the selector.

For clearer identification, prefer the version with a visible name when space allows. The flag-only version does not add a specific text label to the internal link.

tbc-carousel: paginated content

The tbc-carousel organizes its child elements into pages. Each direct element inside the tag counts as one item; there is no additional carousel item tag.

Attribute Type Default Purpose
total-per-page Number 3 Number of items per page at widths of at least 48rem.
interval Number 3000 Autoplay interval, in milliseconds. 0 disables autoplay.

Organizing items

Each item can contain a heading, text, an image, and links. To keep those elements in the same item, place them inside a single element, such as article.

This example displays two items per page on wider screens and changes the page every five seconds: 

<tbc-carousel total-per-page="2" interval="5000">
  <article>
    <h2>First project</h2>
    <p>An introduction to the first project.</p>
  </article>
  <article>
    <h2>Second project</h2>
    <p>An introduction to the second project.</p>
  </article>
  <article>
    <h2>Third project</h2>
    <p>An introduction to the third project.</p>
  </article>
</tbc-carousel>

Placing all articles inside a single div directly under the carousel would make that div count as a single item. Plain text nodes also do not replace the elements that represent items.

Adapting to screen width

Below 48rem, the component displays one item per page. At that width and above, it uses total-per-page. The last page may contain fewer items than the others.

On wider screens, pagination uses clickable indicators. On smaller screens, it displays the current page number and total page count. Previous and next buttons cycle through pages, returning to the first after the last and to the last before the first.

With at most one page, the navigation controls and carousel footer are hidden.

Automatic and manual playback

To use manual navigation only, set interval="0": 

<tbc-carousel total-per-page="1" interval="0">
  <article>
    <h2>First presentation</h2>
    <p>Content visitors can read at their own pace.</p>
  </article>
  <article>
    <h2>Second presentation</h2>
    <p>More content available through the navigation controls.</p>
  </article>
</tbc-carousel>

With a positive interval and more than one page, the carousel provides a pause/play button and a countdown to the next change. Navigating to another page resets that interval.

In the initial automatic mode, playback pauses while the pointer is over the carousel or focus remains inside it. Once those conditions end, the countdown can resume from the remaining time. Pausing with the button keeps playback paused until the visitor starts it again.

When the browser reports a reduced-motion preference, autoplay does not start. If the visitor explicitly selects Play, playback becomes enabled and no longer pauses automatically on hover or focus. The sliding transition remains disabled under reduced motion.

Values and item changes

total-per-page is rounded down and clamped to at least 1; non-finite values become 1. The interval cannot go below zero, and non-finite values disable autoplay. When authoring attributes, use valid numbers with a positive integer item count.

The component observes additions and removals of direct elements to update the item count. Screen width changes also recalculate the grouping. When the page is left, its observers, listeners, and timers are removed.

Icons

Icons have a separate registry in src/web-icons.ts and use the prefix icon-*. The registered elements are icon-home, icon-menu and icon-x, based on the icons Home, Menu and X from @lucide/vue.

You can combine an icon with text that identifies the link destination:

<tbc-link href="#/">
  <icon-home aria-hidden="true"></icon-home>
  <span>Home page</span>
</tbc-link>

In this example, the text communicates the action and the icon provides a visual cue. The current registry does not declare specific attributes for configuring icon-home.

Adding icons as needed

You can add other icons to meet your project's needs. To make them available in fragments:

  1. Import the desired icon from @lucide/vue in src/web-icons.ts.
  2. Add an entry to the object icons, using the existing function createIcon.
  3. Choose a name with the prefix icon-*.
  4. Use the new tag in fragments after updating the application.

The existing entries illustrate the registration pattern:

const icons = {
  ...createIcon('icon-home', Home),
  ...createIcon('icon-menu', Menu),
  ...createIcon('icon-x', X),
};

Adding an icon to the registry makes it available in content; writing a tag with a new name without registering its component does not load the icon automatically.

Appearance and accessibility

Custom elements use the page DOM, without Shadow DOM. This allows them to share Taberna's global styles, but a rule's reach still depends on its selectors and the use of styles marked scoped in components.

You can apply utilities to item content, use theme colors, and create global styles when needed. Do not assume that a class on the outer tag controls every element inside the component.

The carousel uses --carousel-dot for indicators, --carousel-dot-active for the active indicator, and --carousel-counter for the countdown. The playback interval is still configured with the attribute interval, not a theme variable.

Carousel controls are buttons with accessible names and visible focus indicators. Items outside the current page receive inert and aria-hidden, making them unavailable for interaction and hiding them from the accessibility tree while they are not visible.

Carousel interface labels are currently fixed in English. Translating the item content does not automatically translate those labels.

When preparing content, use a proper heading hierarchy, clear link text, and alternative descriptions for images. These practices depend on the item author as well as the component's features.

Creating new components

If the site needs another reusable feature, create a Vue component in src/components/ and register it in src/web-components.ts.

Define the component and its properties

As a structural example, a component named _notice.vue could receive a message: 

<template>
  <p>{{ props.message }}</p>
</template>

<script setup lang="ts">
const props = defineProps({
  message: {
    type: String,
    default: '',
  },
});
</script>

This file would be compiled as part of the application. Vue expressions work in it because it is a component, unlike HTML loaded from fragments.

Register the element

Export Notice through src/components/index.ts and add it to the list imported from @/components in src/web-components.ts: 

import { Notice } from '@/components';

Then add this entry to the object elements, preserving the existing registrations: 

...createElement('tbc-notice', Notice),

Once registered, it could be used in content as follows:

<tbc-notice message="Explore the latest project updates."></tbc-notice>

This component is only an example of creating a new element; tbc-notice is not one of the elements currently registered in Taberna.

Handle integration

Define attributes with clear names, default values, and appropriate validation. For components that receive content through slots, also consider how their styles will reach the elements supplied by the author.

When a style block uses Tailwind directives, place @reference "@/style.css"; at the beginning. Reuse theme variables and utilities for visual consistency.

The current registries do not install Pinia separately in each custom element. Components that use stores depend on Taberna's application initialization; distributing them as standalone widgets would require preparing that integration separately.

Check the new element in a real fragment, with its attributes, content, and interactions. Verify keyboard use, presentation at different screen sizes, and cleanup of any timers or observers. Run npm run typecheck and npm run build and document the tag name and its attributes for others to use.
