Templates

Templates define the visual structure of Taberna pages. They organize the site regions, such as the header, navigation, main content, footer, and sidebar, and offer spaces to receive the content of each one.

Currently, the project has the template src/templates/default.vue. You can customize it or create another layout to meet your site's needs.

Template, theme, and content

These three parts work together but have different responsibilities:

Part Responsibility Example
Template Defines the structure and behavior of the layout. Position the navigation in the header and provide a sidebar.
Theme Defines shared visual values. Configure colors, fonts, borders, and spacing.
Content Fills the regions with information. Present the brand, the menu links, and the text of a page.

To change a footer text, edit the corresponding fragment. To change a shared color, see the theme. To reorganize the regions or create another arrangement of elements, work on the template.

Templates are Vue components and live in src/templates/. They are part of the application code; they are not .htm fragments loaded as content.

How the template connects to the application

The structure passes through three files:

App.vue
  → AppTemplate.vue
    → templates/default.vue

App.vue brings the application together and places the current route page inside AppTemplate.vue. The loading and error screens are also mounted by App.vue, outside the layout template.

AppTemplate.vue imports the chosen template and connects its regions to the fragments and components that should appear in them. The brand and the menus, for example, are loaded by tbc-flux from the complements/ folder of the active language.

The template organizes these elements and receives the current page in its main area. This way, navigation can change the page content while keeping the shared structure.

In the current project, this choice is made in code. There is no automatic template selector, no per-language template configuration, and no independent per-page selection.

Get to know the default template

default.vue offers:

  1. A header that stays at the top while scrolling, with the brand and navigation.
  2. A main area to receive the current route content.
  3. A footer with spaces for the brand, complementary content, body, and copyright.
  4. A “Powered by Mineot” link, defined directly in the template.
  5. A sidebar with its own brand, body, and footer.
  6. A backdrop behind the sidebar when it is open.

Below 48rem, the header navigation is hidden and the sidebar toggle is shown, unless it has been disabled. From that width up, the header navigation appears and the toggle is hidden.

The template also applies styles to its regions, using theme variables and project utilities. The structure and part of the presentation are therefore in the same Vue file.

Slots: the spaces that receive content

A slot is a space in a Vue component that can be filled by whoever uses that component. The template defines where the space appears; AppTemplate.vue specifies what will be placed in it.

This simplified example defines one space for the brand and another for the main content:

<template>
  <header>
    <slot name="header-brand"></slot>
  </header>
  <main>
    <slot></slot>
  </main>
</template>

The header-brand slot has a name. The unnamed slot receives the default content, which in Taberna is used to forward the current page.

Regions available in the default template

The paths in the table are relative to public/content/{language}/.

Slot Region Content currently provided
Unnamed Main area Current route page, forwarded by AppTemplate.vue.
header-brand Brand in the header complements/brand.htm
header-nav Header navigation complements/header-nav.htm
footer-brand Brand in the footer complements/brand.htm
footer-complement Footer complement Links with icons defined in AppTemplate.vue.
footer-body Footer body complements/footer.htm
footer-copyright Copyright complements/copyright.htm
sidebar-brand Brand in the sidebar complements/brand.htm
sidebar-body Sidebar body complements/sidebar-nav.htm
sidebar-footer Sidebar footer tbc-language component.

The slot name does not automatically determine a file name. That connection is explicit in AppTemplate.vue, and a slot can receive HTML, components, or a fragment loaded by tbc-flux.

For example, the header brand is filled in like this, inside the template component used by AppTemplate.vue: 

<template #header-brand>
  <tbc-flux content-file="complements/brand.htm"></tbc-flux>
</template>

The #header-brand syntax indicates which slot will be filled. The content-file attribute indicates which fragment will be fetched in the active language.

Sidebar and settings

Hiding the toggle

The default template has the boolean property hideToggleMenu, whose initial value is false. In a Vue template, it can be provided in kebab-case: 

<Default :hide-toggle-menu="true">
  <slot></slot>
</Default>

The example shows only the property; also keep the slot fills that your layout uses.

This setting hides the toggle. It does not remove the sidebar, does not change the state of an already open menu, and does not force the header navigation to appear on mobile. Before hiding the toggle, make sure there is another way to access the links on small screens.

Opening and closing

The menu starts closed. The template controls its state and offers actions to open and close the region. Currently, it closes when the internal close button is triggered or the backdrop is clicked.

The three sidebar slots also receive a function called close. AppTemplate.vue uses that function to close the menu when its contents receive a click.

The sidebar body slot, for example, is filled in like this:

<template #sidebar-body="{ close }">
  <tbc-flux content-file="complements/sidebar-nav.htm" @click="close"></tbc-flux>
</template>

This is a form of slot with properties: the template provides a function, and whoever fills the slot can use it. The function is not a directive written inside the HTML fragment; the event binding happens in the Vue component.

Customizing the current layout

Choose the file according to the change you want:

Change Where to work
Change the texts or links of a complement Fragment in public/content/{language}/complements/.
Replace the fragment that fills a region src/AppTemplate.vue.
Reorganize the regions or change the menu behavior src/templates/default.vue.
Adjust shared visual values src/styles/theme.css.
Style the HTML of the pages Global styles and utilities appropriate to the content.

Adding a region

Imagine an announcement bar between the header and the main content. To include it in the default template:

  1. 1
    Add a slot called announcement at the desired position in default.vue.
  2. 2
    Fill that slot inside <Default> in AppTemplate.vue.
  3. 3
    Create the corresponding fragment in every enabled language.
  4. 4
    Check the layout and content on small and large screens.

In the template, the new space can be declared like this:

<div>
  <slot name="announcement"></slot>
</div>

In AppTemplate.vue, the fill would be:

<template #announcement>
  <tbc-flux content-file="complements/announcement.htm"></tbc-flux>
</template>

In this example, prepare public/content/pt-br/complements/announcement.htm and the equivalent file in the other available languages. The name is illustrative; this region does not exist in the current template.

Creating your own template

You can start from a copy of the default template to preserve its regions or create a smaller layout with only the spaces your project needs.

1. Create the Vue file

For example, create src/templates/minimal.vue with this structure: 

<template>
  <header>
    <slot name="header-brand"></slot>
    <nav aria-label="Main navigation">
      <slot name="header-nav"></slot>
    </nav>
  </header>

  <main>
    <slot></slot>
  </main>

  <footer>
    <slot name="footer-body"></slot>
    <slot name="footer-copyright"></slot>
  </footer>
</template>

This example defines only the structure. It does not implement its own styles, sidebar, or toggle. Navigation is available in the header; its presentation on different screens needs to be handled in the layout.

2. Connect the template to the application

To use this example, adapt AppTemplate.vue to import the new component and fill the slots it offers: 

<template>
  <Minimal>
    <template #header-brand>
      <tbc-flux content-file="complements/brand.htm"></tbc-flux>
    </template>

    <template #header-nav>
      <tbc-flux content-file="complements/header-nav.htm"></tbc-flux>
    </template>

    <template #footer-body>
      <tbc-flux content-file="complements/footer.htm"></tbc-flux>
    </template>

    <template #footer-copyright>
      <tbc-flux content-file="complements/copyright.htm"></tbc-flux>
    </template>

    <slot></slot>
  </Minimal>
</template>

<script setup lang="ts">
import Minimal from '@/templates/minimal.vue';
</script>

The <slot></slot> inside <Minimal> forwards the page received from App.vue to the main slot of the new template. This pass-through must be preserved so the route content keeps appearing.

The example uses only four named slots. Regions such as the footer brand, social links, and sidebar are no longer part of this layout. When you change your site's template, decide which regions you want to keep and adapt their fills.

3. Check slot compatibility

When the new template keeps the names and properties of the existing slots, you can reuse their fills. If you change the names or remove regions, adjust AppTemplate.vue to match the new structure.

The same applies to functions such as close: if a fill expects to receive it, the new template must provide it or the fill must be adapted. The hideToggleMenu property also belongs to the default template; other templates will only have it if they implement it.

4. Verify the integration

Check the home page, an inner page, the navigation links, and language switching. If there is a sidebar, test opening and closing it through the different forms of interaction.

Run npm run typecheck and npm run build to check the types and the file generation. Browser review is still necessary to evaluate the layout and the interaction.

Styles and considerations when creating templates

Reuse the theme and utilities

Use the theme variables and the tbu-* classes when you want the layout to follow the shared visual settings. If the component's style block uses Tailwind directives, include @reference at the beginning: 

<style scoped>
@reference "@/style.css";

header,
footer {
  @apply tbu-container tbu-block tbu-secondary-bg;
}

main {
  @apply tbu-container tbu-block;
}
</style>

This snippet can be added to the minimal template example. The utilities reuse the theme colors and spacing.

scoped styles help limit rules to the component, but they do not automatically reach all the HTML loaded by tbc-flux. To style the fragment content, use utilities or appropriate global styles. The details are on the themes and utilities pages.

Think about navigation on different screens

When you reorganize the regions, keep navigation access on small screens, avoid content clipping, and check longer texts and links in other languages. The structure should remain usable even when the content grows.

Include accessibility in the interactions

Use semantic elements, buttons for actions, accessible names, and visible focus states. If you create an overlay menu, consider closing with Escape, focus management and restoration, the button's expanded state, and making controls unavailable while the menu is hidden. Respect the reduced-motion preference in animations.

The current sidebar does not yet implement all these measures: the toggle is a clickable SVG, the close button has no accessible name, and there is no handling for Escape, focus, or inert/aria-hidden for the closed region. These recommendations are requirements to guide new layouts, not a description of features already completed in the default template.

Create and share your templates

Over time, various types of templates will be created for different site purposes. Feel free to create your own, adapting the structure to your project's needs.

When sharing a template, explain which regions it offers, which properties it accepts, and how to connect it to the application. This makes it easier for others to use and allows existing content to be reused with fewer adaptations.

If you want to contribute to Taberna, present your proposal in the project repository.
