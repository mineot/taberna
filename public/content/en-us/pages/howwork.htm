How Taberna works

Taberna is a foundation for personal websites, portfolios, and landing pages. It combines an application that organizes the site, editable content files, and features for customizing its appearance.

To work with the project, it helps to understand how these parts connect: where the text lives, how a page loads, how languages are selected, and what must be generated to publish the site.

How the project is organized

Taberna runs entirely in the browser. The Vue application builds the interface structure and loads the HTML files that make up the content. Vue Router handles navigation between pages.

Content is separate from application components. You can revise text or change menu links by editing their HTML fragments. Changes to layout structure and interactive behavior belong in Vue files.

The result can be hosted as static files. The project does not require a backend to display its pages and includes no database or admin panel: editing happens in your repository's files.

The folders pages/ and complements/ help organize content. Files are loaded using the paths specified in links and the application; placing them in these folders does not create menu entries automatically.

How a page is assembled

When the site opens, the application starts detecting the language and builds the shared page structure. Content components wait for the language to be resolved before fetching their files.

Each part has a responsibility:

  1. App.vue combines the application structure, the current route's page, and the loading and error screens.
  2. The component tbc-layout-linear organizes the header, main content, and footer. The sidebar is a separate tbc-sidebar component.
  3. AppTemplate.vue composes the layout and sidebar with the corresponding shared fragments and components.
  4. The router determines which content appears in the main area.
  5. The component tbc-flux fetches the fragment in the active language and inserts its HTML into the page.

For example, the branding displayed in the header, footer, and sidebar comes from the same file, complements/brand.htm. Changing this fragment updates the content used in those three regions on the next load.

Following an internal link loads the new route's content into the main area while keeping the site's shared structure.

Writing content

Files with the extension .htm must contain HTML fragments: only the elements to display in that part of the site. There is no need to repeat the structure of a complete HTML5 document.

Use headings to organize topics, paragraphs to develop ideas, and lists for sequences or groups of items. Fragments can also include links and images.

Published content is interpreted as HTML. Taberna does not convert Markdown automatically; if you use Markdown to draft content, convert it to HTML before publishing the final version.

Fragments can use style classes and custom components registered by the project. Vue expressions and directives, such as interpolation and v-if, are not compiled in these files. Behavior that depends on Vue must be implemented in application components.

These files are content authored by the site owner. The loader does not sanitize HTML, so publish only content you know and have reviewed.

Pages and navigation

Internal links use the format with #. The home page is at #/, and the language selector is at #/language.

For content pages, the part after #/ identifies the fragment's path within the active language folder. For example: 

Address: #/pages/howwork.htm
Active language: en-us
File: public/content/en-us/pages/howwork.htm

The same address, with Portuguese active, looks for public/content/pt-br/pages/howwork.htm. The language does not need to appear in the link.

Adding a page

To create a page called About, follow these steps:

  1. Create pages/about.htm inside the folder for each enabled language.
  2. Write the corresponding content in each language, keeping the same file name and path.
  3. Add the link to the navigation fragments where you want the page to be available.
  4. Check page access and language switching in your local environment.

The link can be written as follows:

<tbc-link href="#/pages/about.htm" text="About"></tbc-link>

The header menu and sidebar menu have separate files: complements/header-nav.htm and complements/sidebar-nav.htm. Edit both when you want the page to appear in both navigation areas.

For this type of page, the catch-all route already forwards the path to the loader; there is no need to register a Vue route for each fragment.

Paths and loading failures

Fragment paths must end in .htm. In the value passed to the loader, do not use a leading slash, backslashes, empty segments, or ... Subfolders are allowed, as in pages/about.htm.

If a file is missing, cannot be loaded, or the host returns a full HTML document instead of the fragment, the application displays its error screen. There is currently no dedicated not found content page or automatic lookup of the translation in another language.

How languages work

The file public/config/languages.json contains four pieces of information:

  • default: the default language.
  • available: the list of enabled languages.
  • flags: the flags associated with each language.
  • names: the names displayed in the selector.

The current configuration is:

{
  "default": "en-us",
  "available": ["pt-br", "en-us"],
  "flags": { "pt-br": "🇧🇷", "en-us": "🇺🇸" },
  "names": {
    "pt-br": "Português (Brasil)",
    "en-us": "English (United States)"
  }
}

At startup, Taberna looks for an available language in this order:

  1. The preference saved in the browser during a previous visit.
  2. The language preferences reported by the browser.
  3. The default language from the configuration.
  4. The first available language, if the default is not in the list.

Use lowercase identifiers, such as pt-br and en-us, and keep those names in the content folders. Matching uses the complete identifier: a preference for pt is not automatically converted to pt-br.

When another language is selected, the preference is saved in the browser's local storage and the page reloads, keeping the current page address. If the browser prevents that preference from being saved, the selection may not persist.

To enable another language, add its information to the configuration and prepare all corresponding fragments, including pages and shared content. You write the translations; there is no automatic translation. Language-based organization applies to content, while some interface messages are still fixed in English.

Customization: the role of each feature

Themes

The theme defines the shared visual identity: colors, fonts, spacing, borders, and other details. Its variables live in src/styles/theme.css and are used by the project's styles and utilities.

Changing these definitions lets you adjust the appearance of several regions consistently. To explore the visual configuration, see the page on Themes.

Layout and composition

src/AppTemplate.vue composes tbc-layout-linear and tbc-sidebar, filling their slots with shared content fragments. The layout uses the header and footer components from src/components/.

You can replace the fragments in each region or rearrange the components in the composition. The guide to shows the available slots and how to fill them.

Components

Components provide reusable features and behavior. For navigation and actions, use tbc-nav and tbc-link. Other available components include tbc-flux, which loads fragments, tbc-language, which links to the language selector, and tbc-carousel, which organizes items in a carousel.

Each component has its own purpose and may provide configuration attributes. The page on components covers this topic separately.

Utilities

Utilities are classes that apply visual rules directly to HTML elements. Taberna uses Tailwind CSS and its own classes with the prefix tbu-*, defined in src/styles/utilities/.

They help apply theme colors, spacing, borders, and other features without repeating the same CSS rules in every content block. See the details on the page about utilities.

From development to publishing

Prepare your copy

Have Git, Node.js, and npm installed. The project's reference environment uses Node.js 24. You can fork Taberna on your GitHub account to keep your customizations in your own repository.

To start from the original repository:

git clone https://github.com/mineot/taberna.git
cd taberna
npm ci

If you created a fork, replace the URL in the command with your repository's URL.

Work locally

Start the development server:

npm run dev

Open the address shown in the terminal. Edit the content fragments and check the result in the browser. To review English, select English (United States) on the language page. If needed, reload the page to fetch the updated files again.

A practical sequence is to customize the branding and home page, prepare internal pages, update menus, and check the content in each language. Then work on the theme and other visual changes.

Generate and review the production build

When you want to prepare the site for publishing, run:

npm run build

This command checks TypeScript and generates production files in dist/. Public files, including content fragments, are copied to that output. New classes in fragments also require this build to be included in the production CSS.

To check the result locally:

npm run preview

Preview lets you review the build before publishing it. Check links, images, pages, and language switching; a successful build does not verify that every translation and link destination exists.

Publish the site

Upload the contents of dist/ to your chosen static hosting service. The upload process depends on the service; the project does not include an automated publishing workflow.

If you publish to a subdirectory, check asset paths in fragments. For example, /images/logo.png points to the domain root, while images/logo.png is relative to the base URL of the displayed page. Paths are not resolved relative to the fragment's folder and are not rewritten automatically by the build.

Keep changes in the source files, generate a new build, and publish the updated output. This keeps your repository as the reference for your site's content and customizations.
