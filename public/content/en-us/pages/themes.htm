Theme

The theme gathers Taberna's shared visual settings. Colors, fonts, spacing, borders, and other details are defined in variables that the styles and components use to build the site's appearance.

The starting point for customizing these definitions is the file src/styles/theme.css. This page presents the current settings and examples of how to adjust them for your project.

How the theme works

A variable holds a value that can be reused across several CSS rules. In Taberna, for example, --color-primary defines the color used by the utility tbu-primary-bg. Because that utility is applied to the page background, changing the variable changes that background.

The path from the setting to the visual result is:

Variable in the theme → style rule or utility → element on the page

The change affects only the elements that use that variable, directly or through another rule. An element with a color or spacing defined independently keeps following its own setting.

The theme also does not select another layout: that responsibility belongs to the templates. You can customize the appearance while keeping the site's current structure.

Where to configure

The file theme.css has two main blocks:

  1. @theme: defines the font families integrated with Tailwind's utilities.
  2. :root: defines the shared variables for colors, spacing, borders, layers, and other Taberna resources.

The examples on this page indicate which block to change. Replace the existing values of the corresponding variables, preserving the other settings.

Other files take part in the presentation:

File Responsibility
src/styles/fonts.css Registers the local fonts with @font-face.
src/styles/utilities.css Defines the tbu-* classes that apply theme values.
src/styles/app.css Applies global styles, including the page background and typography.
src/style-customs.css Contains the custom content styles.

The variables in :root can be consumed with var(...) in CSS. They do not automatically create a Tailwind utility with the same name; Taberna's own classes are defined in utilities.css.

Site colors

The colors are organized into three families:

Family Current use
primary Main page background and main text.
secondary Supporting regions, such as the footer, sidebar, and panels, plus secondary text.
asset Highlights, links, and other elements that draw attention.

Each family has a base color, a soft variation, and an opaque variation.

Variable Current value
--color-primary var(--color-neutral-600)
--color-primary-soft var(--color-neutral-200)
--color-secondary var(--color-neutral-800)
--color-secondary-soft var(--color-neutral-400)
--color-asset var(--color-emerald-500)
--color-asset-soft var(--color-emerald-300)

The background utilities use the base color, while the text ones use the soft variation. For example, tbu-secondary-bg applies --color-secondary, and tbu-secondary-text applies --color-secondary-soft.

The soft colors are configured separately: changing the base color does not automatically change its soft version.

Variations with transparency

Despite the name opaque, these variables represent versions with transparency. The current setting mixes 30% of the base color with transparent: 

--color-primary-opaque: color-mix(in oklab, var(--color-primary) 30%, transparent);
--color-secondary-opaque: color-mix(in oklab, var(--color-secondary) 30%, transparent);
--color-asset-opaque: color-mix(in oklab, var(--color-asset) 30%, transparent);

In these expressions, oklab is the color space used for the mix. Increasing the color percentage makes the result less transparent; decreasing the percentage makes what is behind more visible.

Because these variations reference the base color, they follow its changes as long as that relationship is kept.

Changing the highlight color

To change the green highlight to blue, change these two variables inside :root: 

--color-asset: var(--color-blue-500);
--color-asset-soft: var(--color-blue-300);

The --color-asset-opaque version starts using the new base color. Links that use tbu-asset-link start from the soft color and receive darker variations on hover or press.

You can also use CSS values directly, such as #2563eb, instead of references to the Tailwind palette. When combining backgrounds and texts, check the readability of each color pair.

Fonts

The font families live in the @theme block:

Variable Current main font Corresponding utility
--font-sans Roboto font-sans
--font-serif Roboto Serif font-serif
--font-mono Roboto Mono font-mono
--font-fancy Italianno font-fancy

Each definition can also list alternative fonts. The browser looks for the first available one and falls back to the next when needed. The page uses font-sans as its base; specific sections can choose another family.

To use the serif font already included in the project as the main family, for example, change --font-sans inside @theme: 

--font-sans: 'Roboto Serif', ui-serif, Georgia, serif;

Adding your own font

Taberna's fonts are hosted with the site. To include another family:

  1. 1
    Place the font files in public/fonts/.
  2. 2
    Register the family in src/styles/fonts.css, providing the correct path, format, weight, and style.
  3. 3
    Use the registered name in the desired font variable in theme.css.
  4. 4
    Check the weights and styles used by the content, including bold and italic when available.

This example assumes you added a regular-weight WOFF2 file at public/fonts/MyFont/regular.woff2. In fonts.css, the registration would be: 

@font-face {
  font-family: 'My Font';
  font-style: normal;
  font-weight: 400;
  font-display: swap;
  src: url('/fonts/MyFont/regular.woff2') format('woff2');
}

Then, in the @theme block of theme.css: 

--font-sans: 'My Font', ui-sans-serif, system-ui, sans-serif;

The name and file are illustrative. Only changing the variable does not install or load a font that is not yet available.

Spacing and adaptation to screens

The theme has two spacing families:

  1. --container-*: controls the horizontal padding applied by tbu-container.
  2. --block-*: controls the vertical padding applied by tbu-block.

These variables hold multipliers of the --spacing unit, not pixel values or maximum content widths. The calculation used by the utilities is: 

padding-inline: calc(var(--spacing) * var(--container-sm));
padding-block: calc(var(--spacing) * var(--block-sm));

The suffixes select values according to the screen width:

Width range Suffix Value of --container-* Value of --block-*
Below 48rem sm 4 6
From 48rem up to before 64rem md 14 6
From 64rem up lg 24 6

These ranges are defined in Taberna's utilities. In the larger range, the lg rule replaces the value applied by the md rule.

To increase the horizontal space on larger screens, you can change in :root: 

--container-sm: 4;
--container-md: 16;
--container-lg: 32;

The space is applied on each side of the element that uses the utility. Larger values leave less width available for your content.

These settings do not replace all the site's spacing. Elements that use their own classes, such as p-4 or gap-2, keep their values. The same applies to a region that uses tbu-container but defines vertical padding another way.

Borders and rounding

The borders that use the tbu-border utilities share these definitions:

Variable Current value Purpose
--border-color var(--color-secondary-soft) Border color.
--border-size 1px Border thickness.
--border-style solid Line style.
--rounded var(--radius-lg) Radius applied by tbu-rounded.

The per-side border versions, such as tbu-border-top, use the same values. To customize them, change in :root, for example: 

--border-color: var(--color-neutral-500);
--border-size: 2px;
--border-style: solid;
--rounded: 0.75rem;

Changing --rounded affects elements with tbu-rounded. Classes such as rounded-sm have another definition and do not follow that variable.

Background texture

The --texture variable indicates the image applied by tbu-texture. The utility repeats that image over the element's background: 

--texture: url('/images/texture.png');

To replace the texture, add the new image in public/images/ and adjust the path. For example, if the file is named my-texture.png: 

--texture: url('/images/my-texture.png');

To disable the image on elements that use this setting:

--texture: none;

The background color remains defined by the color rules. In the current theme, the texture appears on the general background and in other regions that use tbu-texture.

Shadows and backdrop

Shadows

--shadow-color controls the color used by tbu-shadow. Currently, it mixes black with transparency: 

--shadow-color: color-mix(in oklab, var(--color-black) 50%, transparent);

You can reduce the color intensity, for example:

--shadow-color: color-mix(in oklab, var(--color-black) 25%, transparent);

This variable changes the shadow color. Its offsets and blur radii are defined in the utility and remain the same.

Background behind the sidebar

--backdrop-color is consumed by tbu-backdrop, used in the backdrop behind the sidebar. The utility also applies texture and blur to what is behind.

In the current setting, this variable references --color-secondary-bg, which is not defined. The tbu-secondary-bg class exists, but a CSS class does not replace a variable. Therefore, this expression does not provide a valid background color.

When customizing this value, one option is to reference the existing secondary color:

--backdrop-color: color-mix(in oklab, var(--color-secondary) 30%, transparent);

This snippet is a suggested adjustment for your theme; the invalid reference is still present in the project's current file.

Layers and transitions

Stacking order

The --z-* variables organize the stacking of the elements that use them:

Variable Current value Current use
--z-backdrop 100 Backdrop, through tbu-backdrop.
--z-sidebar 150 Sidebar of the default template.
--z-loader 999 Declared in the theme, but not yet used by the loader.

In the current template, the sidebar sits above its backdrop. When you change these values, keep that relationship. The result of z-index also depends on the stacking contexts created by CSS.

The loading screen still uses z-200, and the error screen uses z-300 directly. Changing only --z-loader does not change the position of those screens.

Transition duration

--duration defines the duration used by tbu-duration, which also applies the ease-in-out transition curve. The current value is 200ms.

To reduce this duration, change in :root:

--duration: 150ms;

The variable affects the transitions connected to that utility. It does not control all animations, the carousel playback interval, or the loader animation timing. When creating new effects, also consider the visitor's reduced-motion preference.

Component visual settings

The theme includes three variables specific to the carousel:

Variable Current value Purpose
--carousel-dot Mix of --color-primary-soft at 40% with transparent Color of the page indicators.
--carousel-dot-active var(--color-asset) Color of the active indicator.
--carousel-counter var(--color-primary-soft) Color of the page counter.

These values follow the referenced colors as long as the expressions are kept. You can also assign your own colors to the controls without changing the rest of the palette.

The behavior settings, such as the number of items and the playback interval, belong to the component. That topic is on the components page.

Customization example

The example below combines a blue highlight, subtle borders, and more horizontal space on larger screens. Replace the corresponding variables inside the existing :root block in theme.css: 

--color-asset: var(--color-blue-500);
--color-asset-soft: var(--color-blue-300);

--border-color: var(--color-neutral-500);
--border-size: 1px;
--border-style: solid;
--rounded: 0.75rem;

--container-sm: 4;
--container-md: 16;
--container-lg: 32;

--block-sm: 6;
--block-md: 8;
--block-lg: 10;

The other variables can keep their current values. The transparency expressions and the carousel's active indicator that reference the highlight color start following the blue.

After the change, check the site on small and large screens. Observe the text contrast, how the links read in their normal and interactive states, the space available for the content, and the controls of the components your site uses.

To review the production result, generate a new build with npm run build and check it with npm run preview. The build checks and generates the files; visual evaluation is still necessary to check the combination you chose.

To learn about the classes that apply these settings to the content, continue to the utilities page.
